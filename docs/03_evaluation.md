# 既存言語の評価

[02_requirements.md](02_requirements.md) の38項目を、15言語について評価した。**評価は Claude の記憶と見立てによる。検索で確かめていない。** ツールや版で変わる。

## 評価の基準

| 記号 | 意味 | 点 |
|---|---|---|
| ◎ | 言語機能として満たす | 3 |
| ○ | 満たすが範囲が限られる | 2 |
| △ | 任意の機能、慣習、外部ツール、近似のいずれか | 1 |
| × | 無い | 0 |

満点：単純合計 93 点、重み付き 324 点（重みの合計108の3倍）。データは `data/evaluation.csv`、集計は `python3 tools/score.py`。

## 読み取れること

- 重みを付けても順位はほぼ変わらない。変わったのは Koka が Swift を上回った点だけ（単純合計は同点）。
- 最高の F\* でも重み付きで52%。どの言語も要求の半分を超えない。
- 上位4つは、検証・効果型・内容ハッシュを言語に持つもの。主流言語では Rust が最も高い（5位）。Python は12位、C は14位。
- 15言語すべてが × なのは、**9（落ちた理由の3択）、20（細かさと確からしさの軸）、23-3（保存の種類の宣言）** の3項目。8（失敗領域だけ割る）と 12（洗練の予算）は DSPy 系が △ を取っただけ。
- **偏りがある。** 要求の一覧は、Dafny・Lean・Rust の機能を見ながら導いた部分が多く、検証系の言語に有利に出る。一覧が「検証系を良しとする」前提を含んでいる（見立て）。

## 評価で割り切った点

- **Lisp 系**は Common Lisp と Racket をまとめた。契約（2）や段階的型付け（7）は Racket の機能を数えている。
- **Dafny** の「未反証と証明済みの区別」（21）は、`assume` の追跡を根拠に ○（記憶）。
- **DSL** は、メモリ安全（23-1、23-2）をホスト言語から引き継いだ形で採点した。
- **Lean** の 17（機械語まで続く）は △、18（変換の検証）は ×。C を経由し、コンパイラは検証されていないため（[01_discussion.md](01_discussion.md) 11）。
- 要求2の `assert` は4つの主流言語とも持つが、契約を表す言語機能ではない。要求22の △ は、外部のミューテーションテスト（mutmut、cargo-mutants、Mull、Stryker など）を数えている。
- 要求21は、Kani や Frama-C のような外部の検証器があるが、未反証と証明済みを言語の中で区別して残す仕組みではないので ×。
